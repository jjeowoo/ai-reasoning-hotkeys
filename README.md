# ai-reasoning-hotkeys

StrokesPlus.net의 `Ctrl + Alt + ↑ / ↓`로 ChatGPT Windows 앱과 Claude Desktop의 추론 강도를 한 단계씩 바꿉니다.

| 앱과 모델 | 단계 순서 |
|---|---|
| ChatGPT Windows · ChatGPT 모드와 Codex 모드 · GPT-6.1 Sol | Light → Medium → High → Extra High → Ultra |
| Claude Desktop · Code 탭 · Opus 5.5 | 낮음 → 중간(보통) → 높음 → 엑스트라 → 최대 → Ultracode |
| Claude Desktop · Chat 탭 · Opus 5.5 | 낮음 → 중간 → 높음 → 엑스트라 → 최대 |

위쪽 방향키는 한 단계 올리고 아래쪽 방향키는 한 단계 내립니다. 양 끝에서는 현재 단계를 유지합니다. 다른 모델에서는 변경을 중단하고, 다른 앱에서는 원래 키 조합을 전달합니다.

## 설치

Windows, x64 .NET Framework 및 StrokesPlus.net이 필요합니다. StrokesPlus.net 0.5.7.8의 기본 설치 경로(`C:\Program Files\StrokesPlus.net`)에서 확인했습니다.

1. 저장소를 내려받습니다. 권장 폴더는 Windows 문서 폴더의 `_ETC\ai-reasoning-hotkeys`입니다.
2. 실행 중인 StrokesPlus.net을 트레이 메뉴의 **Exit**로 종료합니다.
3. 내려받은 폴더에서 다음 명령을 실행합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Install.ps1
```

설치 프로그램은 StrokesPlus 설정을 백업하고 `AI Reasoning` 분류에 두 단축키를 등록한 뒤 StrokesPlus를 실행합니다. 다른 설정과 단축키는 보존합니다. 실행 경로는 설치한 폴더에 맞춰 생성하므로 다른 폴더에 설치해도 됩니다. 폴더를 이동하거나 이름을 바꾸면 새 위치에서 설치를 다시 실행하세요.

설정 변경 없이 확인하거나 두 단축키만 제거하려면 다음 명령을 사용합니다.

```powershell
.\Install.ps1 -DryRun
.\Install.ps1 -Undo
```

`Up.js`와 `Down.js`는 수동 등록용 스크립트입니다. 기본 경로는 Windows 문서 폴더의 `_ETC\ai-reasoning-hotkeys`이며, 다른 위치에서는 `reasoningHelper`를 변경하세요. `Hotkeys.json`은 설치 프로그램이 사용하는 템플릿입니다.

## 동작

팝업이 닫혀 있으면 접근성 정보에서 현재 모델과 강도, 버튼 위치를 읽고 실제 마우스 클릭으로 엽니다. 이미 열려 있으면 그대로 인식합니다. 고정된 안내 문구를 StrokesPlus의 이미지 검색으로 찾아 슬라이더의 현재 흰 손잡이를 읽고, 목표 칸을 클릭한 뒤 변경을 확인합니다.

Claude Desktop은 접근성 정보를 요청받은 뒤에 만들기 때문에, 앱을 켠 뒤 첫 조회에는 창 테두리의 버튼만 나올 수 있습니다. 이때는 모델 버튼이 나타날 때까지 최대 1.5초 동안 다시 조회합니다. 다른 모델의 버튼이 보이면 기다리지 않고 중단합니다.

Claude Desktop의 Chat 탭에는 노력 버튼과 슬라이더가 없어서 이미지 검색을 쓰지 않습니다. 모델 버튼을 클릭해 메뉴를 열고, `노력` 줄을 클릭해 하위 메뉴를 연 뒤, 목표 단계의 항목을 클릭합니다. 항목은 메뉴 안에서만 접근성 이름으로 찾으므로 대화 내용과 혼동하지 않습니다. 변경은 메뉴의 선택 표시, `노력` 줄의 값, 모델 버튼의 이름 중 하나로 확인합니다. 메뉴가 입력란 클릭을 닫는 데만 쓰는 경우가 있어, 입력란 포커스가 확인되지 않으면 한 번만 더 클릭합니다.

변경 후 채팅 입력란을 클릭합니다. GPT에서는 팝업이 보이는 동안 입력란에 포커스가 있다는 접근성 정보만으로 클릭을 생략하지 않습니다. **팝업 닫힘과 입력란 포커스**를 함께 확인하고, 확인되지 않으면 활성 창과 위치를 다시 검사한 뒤 한 번만 재시도합니다. Claude는 입력란을 한 번 클릭합니다.

각 클릭 전에 Ctrl·Alt·방향키가 놓였는지 확인합니다. Esc, SendKeys, 강제 SetFocus는 사용하지 않습니다. 활성 창이 바뀌거나 모델·이미지·입력란 위치를 확인할 수 없으면 추가 클릭을 중단합니다.

GPT의 팝업은 약간 비쳐서, 뒤에 대화 글이 있으면 팝업의 픽셀이 몇 단계 어두워집니다. 그래서 GPT 팝업의 기준 문구는 정확히 일치하지 않아도 모든 픽셀이 채널당 16단계 안에서 일치하면 인식합니다. 측정한 차이는 최대 5단계였습니다.

참조 이미지는 한국어 UI와 밝은 테마에서 캡처했습니다. 모델 이름, 화면 배율 또는 앱 UI가 달라져 이미지와 일치하지 않으면 전환을 중단합니다. 테마와 배율이 다른 환경은 별도 조정이 필요합니다.

## 빌드와 검사

```powershell
.\Build.ps1
.\ReasoningSwitch.exe --selftest
```

빌드는 네 C# 소스를 x64 실행 파일로 컴파일하고 자체 검사에 통과한 파일만 적용합니다. 이미지 검사에는 설치된 StrokesPlus.net이 필요합니다. `--selftest`는 첨부 이미지와 생성한 검사 캔버스만 사용하며 앱 화면을 캡처하거나 입력하지 않습니다.

사용 중인 실행 파일을 건드리지 않고 빌드만 확인하려면 다른 폴더를 지정합니다. 참조 이미지도 그 폴더로 함께 복사합니다.

```powershell
.\Build.ps1 -OutputDirectory C:\Temp\reasoning-build
```

빌드 이름은 `ReasoningSwitch.cs`의 `BuildName` 한 곳에서 정의하고, `Build.ps1`은 그 값을 읽어 결과에 표시합니다.

현재 버전은 **22-translucent-gpt-popup**입니다. 단계 이름·양방향 이동·경계, Chat 탭 메뉴 항목 이름과 다섯 단계의 경계, ChatGPT 모드 이름, 뒤 내용 때문에 어두워진 GPT 팝업의 인식, 제목에 모델 이름이 들어간 사이드바 세션의 거부, 모델 버튼과 창 테두리 버튼의 구분, 실제 참조 이미지의 손잡이, 팝업이 남은 상태의 포커스 정보, 첫 클릭이 무시된 경우의 재시도, 입력란 클릭 위치를 검사합니다. 최적화 검사에는 일부 글자만 일치하는 가짜 후보의 거부와 실제 팝업 복구, 검색 영역이 창 밖으로 벗어나는 경우, 잘라낸 이미지의 여섯 단계 및 다른 모니터 좌표 변환도 포함됩니다.

## 성능

Claude는 처음 팝업을 찾을 때 버튼 주변부터 검색하고, 찾은 뒤에는 최대 320×180 영역을 캡처합니다. 작은 범위에서 찾지 못하면 전체 창을 다시 검색하므로 팝업 위치가 바뀐 경우도 복구합니다. 참조 이미지는 실행 중 한 번만 읽습니다.

큰 이미지에서 공백으로 시작하는 검색 키는 글자 부분을 먼저 찾습니다. 작은 키가 일치해도 원래 안내 문구의 모든 픽셀을 검증한 뒤 좌표를 반환합니다. 일부 글자만 같은 후보가 먼저 발견되면 원래 검색으로 실제 팝업을 찾습니다.

Claude의 모델·추론 버튼을 한 번의 접근성 조회에서 찾습니다. 이미 채팅 입력란에 포커스가 있으면 해당 입력란의 메타데이터만 읽고 전체 입력란 검색을 생략합니다. 팝업이 닫힌 후 강도는 기존 버튼의 최신 이름에서 읽고, 버튼이 사라지거나 이름을 확인할 수 없을 때 다시 찾습니다. 키 해제 확인, 변경 확인, 팝업 닫힘·입력란 포커스 확인은 유지합니다.

2026-10-08의 저장된 이미지와 흰색 합성 캔버스 시험에서 Claude의 2560×1410 검색은 기존 약 634–850ms/회에서 약 30–70ms/회로 줄었습니다. 화면 캡처·앱 반응·접근성 조회가 제외된 검색 함수 측정이므로 실제 전환 시간이나 화면 멈춤 개선율을 뜻하지 않습니다. 빌드 19는 2026-10-08에 실제 앱에서 전환을 확인했습니다. ChatGPT에서는 GPT-6.1 Sol이 Extra High로, Claude Desktop에서는 Opus 5.5가 엑스트라로 바뀌었고, 두 경우 모두 이미지로 결과를 확인한 뒤 입력란 포커스가 돌아왔습니다. 빌드 20의 재조회는 자체 검사만 통과했고, 앱을 켠 직후의 첫 실행에서는 아직 확인하지 않았습니다. Claude Desktop의 Chat 탭은 빌드 21로 2026-10-09에 실제 전환을 확인했습니다(엑스트라에서 높음으로, 메뉴에서 확인 후 입력란 포커스 복귀). ChatGPT 모드는 빌드 21에서 대화 글이 팝업 뒤에 있을 때 이미지를 찾지 못했고, 빌드 22로 같은 날 Ultra에서 Extra High로 바뀌는 것을 이미지로 확인했습니다. 다만 그 실행에서는 마무리 단계의 포커스 조회가 사라진 요소 때문에 중단되어, 팝업 닫힘은 확인되지 않은 것으로 기록됐습니다.

## 진단 파일

- `last-result*.txt`: 최근 실행 결과
- last-action-chatgpt.txt, last-action-claude.txt: 앱별 단계·소요 시간·포커스 결과, 접근성 조회·이미지 검색·캡처별 시간
- `last-diagnostic*.txt`: 오류 발생 시 모델·추론 컨트롤 정보. 대화 내용이 목록 항목으로 노출되는 화면이 있어 목록 항목은 기록하지 않습니다.
- `chat-input-*.txt`: 같은 창에서 재사용하는 창·프로세스 번호와 입력란 위치
- `StrokesPlus.before-*.json`: 설치 전 개인 설정 백업

실행 파일은 네트워크나 클립보드에 접근하지 않으며 대화를 전송하지 않습니다. 입력란의 본문을 읽거나 로그로 저장하지 않습니다. 화면 캡처는 이미지 검색을 위해 메모리에서만 사용합니다. 개인 설정 백업과 진단·위치 파일은 Git에서 제외됩니다.
